# Журналы работы

У каждой ветки свой журнал: что сделано, что проверено, чем закончилось и что
дальше. По журналу любой участник через месяц поймёт, что происходило
в ветке, даже если она так и не дошла до `main`.

Файл называется по ветке, `/` заменяется на `-`: ветка
`maxat/esp32-two-motors` ведёт журнал `maxat-esp32-two-motors.md`. Файл правит
только автор ветки, поэтому при слиянии журналы не конфликтуют.

## Что записывать

- изменения в файлах, коротко: подробности в сообщениях коммитов;
- действия без файлов: прошивка, смена настроек мотора, замеры, заказ
  деталей, договорённости;
- что пробовали и что не получилось, и почему;
- открытые вопросы.

Испытание с измерениями оформляется отдельным протоколом в
[`docs/testing/`](../testing/), в журнал идёт ссылка на него. Инженерное
решение оформляется ADR в [`docs/architecture/adr/`](../architecture/adr/).

## Формат

Записи по датам, новые внизу. Запись делается в тот же день и пушится вместе
с работой. Пустые пункты можно пропускать. Пример:

```markdown
# maxat/esp32-two-motors

Задача: #12. Консоль ESP32 для двух моторов AK80-64.

## 2026-10-09

- Сделано: перенёс протокол MIT в firmware/lib/ak_motor, тесты проходят.
- Проверено: стенд, мотор ID 4 через MCP2515, 400 ответов из 400.
- Не получилось: на SPI 4 МГц через преобразователь уровней теряются
  кадры, вернул 1 МГц.
- Вне репозитория: сменил CAN ID второго мотора на 5 через R-Link.
- Дальше: подключить второй мотор, проверить одновременное вращение.
```
