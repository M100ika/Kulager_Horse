# ak80-mega-test

Стендовый тест мотор-редуктора CubeMars AK80-64: Arduino Mega 2560 + модуль
MCP2515 (CAN по SPI). Проверяет связь с мотором и его отклик в MIT-режиме,
а интерактивная консоль (`src/main.cpp`) позволяет управлять мотором
командами из терминала и собирать статистику.
Это не прошивка модуля: основная прошивка будет в `firmware/` на ESP32.

## Что проверяется

`test/test_protocol`: кодирование команд и разбор ответов. Железо не нужно,
запускается на ПК и на Mega.

`test/test_motor`: проверка на стенде, тесты идут по порядку:

| Тест | Что проверяет |
|---|---|
| `test_can_controller_init` | MCP2515 отвечает по SPI и настроен на 1 Мбит/с |
| `test_motor_responds` | мотор отвечает на вход в режим управления; если на шине видны кадры Servo-режима, тест подскажет переключить режим |
| `test_rest_state` | вал неподвижен без команды, нет кода ошибки, температура драйвера ниже 70 °C |
| `test_link_stability` | 400 команд с частотой 200 Гц: доля ответов не ниже 98 %, задержка ответа |
| `test_position_move` | вал плавно поворачивается на `kMoveRad` (сейчас 180°) и возвращается с точностью 0,05 рад; момент при заклинивании ограничен `kMoveMaxTorque` |
| `test_exit_motor_mode` | выход из режима управления |

После каждого теста, в том числе упавшего, мотор получает команду нулевого
момента (вал свободен). Все пороги задаются в `include/test_config.h`.

`test/test_bus_scan`: поиск мотора, когда его CAN ID или режим неизвестны.
Секунду слушает шину (мотор в Servo-режиме сам шлёт расширенные кадры), затем
шлёт вход в режим управления на ID 1–127 и печатает все ответы. Ответившему
мотору сразу уходят нулевой момент и выход из режима, вал не двигается.

## Оборудование

- Arduino Mega 2560
- модуль MCP2515 + TJA1050, **желательно с кварцем 16 МГц**
- AK80-64 в MIT-режиме. Заводской CAN ID 1, у стендового мотора ID 4
  (найден `test_bus_scan`)
- лабораторный блок питания 24–48 В с ограничением тока (мануал: номинал
  48 В, допустимо 18–52 В)

AK80-64 работает только на 1 Мбит/с. На большинстве дешёвых модулей MCP2515
стоит кварц 8 МГц, и на такой скорости он работает вне спецификации. Если
кварц 8 МГц (надпись `8.000` на корпусе), лучше заменить модуль или кварц на
16 МГц. С `kMcpCrystalMhz = 8` стенд работает (400 ответов из 400 на коротком
проводе), но запаса по таймингу нет: при длинной шине возможны потери кадров.

## Подключение

| Arduino Mega | MCP2515 |
|---|---|
| 5V | VCC |
| GND | GND |
| 53 | CS |
| 51 | SI |
| 50 | SO |
| 52 | SCK |
| — | INT (не используется) |

| MCP2515 | AK80-64 |
|---|---|
| CAN H | CAN_H |
| CAN L | CAN_L |
| GND | GND разъёма CAN, если он есть |

На шине должно быть ровно два терминатора по 120 Ом. На модуле MCP2515 это
перемычка J1. Своего терминатора у AK80-64 нет: с J1 между CAN_H и CAN_L
120 Ом, без J1 около 25 кОм, то есть без J1 терминатора на шине нет совсем.
На коротком стенде хватает одной J1, по правилам второй резистор 120 Ом ставят
у разъёма мотора, и тогда при выключенном питании между CAN_H и CAN_L около
60 Ом.

У мотора два разъёма CAN, CAN in и CAN out. На стендовом моторе через CAN in
шина залипала в доминантном состоянии даже при обесточенном моторе (TEC=0,
REC=128), через CAN out работает. Причину не выясняли: подключайтесь к CAN out.

## Перед запуском

1. Мотор жёстко закреплён на стенде. Вал свободен: **без повода и нагрузки**.
2. Мотор переведён в MIT-режим, CAN ID записан в `kMotorId`. Режим и ID
   задаются в программе CubeMars Upper Computer через R-Link.
3. Блок питания с ограничением тока 2–3 А для первого включения.
4. Рядом есть кнопка или выключатель, обесточивающие мотор.

## Запуск

```bash
cd tools/ak80-mega-test

pio test -e native                  # тесты протокола на ПК
pio test -e mega -f test_motor -v   # проверка мотора, -v выводит измерения
pio test -e mega -f test_bus_scan -v  # поиск CAN ID мотора
pio test -e mega                    # всё на Mega
```

Порт определяется автоматически. Если нужно указать явно:
`--upload-port /dev/ttyACM0`. Если в Linux нет доступа к порту, добавьте
пользователя в группу `dialout` и перелогиньтесь.

С флагом `-v` тест печатает позицию, скорость, момент, температуру, задержку
связи и пиковый момент при движении.

## Интерактивная консоль

Прошивка `src/main.cpp`: мотор управляется текстовыми командами через USB.
Пины, кварц, CAN ID и стартовые kp, kd, maxt берутся из `include/test_config.h`.

```bash
cd tools/ak80-mega-test
pio run -e mega -t upload -t monitor   # собрать, прошить, открыть терминал
pio device monitor                     # только терминал, если уже прошито
```

Команда набирается целиком и уходит по Enter. Выход из терминала: Ctrl+C.
Во время прошивки терминал и пульт должны быть закрыты, иначе порт занят.
После `pio test` в Mega остаётся тестовая прошивка, консоль нужно прошить
заново.

Вместо терминала можно работать с пультом [`tools/ak80-gui`](../ak80-gui/README.md):
те же команды кнопками, графики телеметрии, таблица ходов и запись в CSV.

При открытии терминала Mega перезагружается, выводит мотор из режима
управления (вал свободен) и печатает справку.

### Команды

Углы в градусах выходного вала, скорость в °/с. Дробные числа можно писать
и через точку, и через запятую.

| Команда | Что делает |
|---|---|
| `m <угол>` | ход в абсолютную позицию, например `m 90` (длинная форма `move`) |
| `r <угол>` | поворот от текущей уставки, например `r -45` (`rel`) |
| `v <скорость>` | вращение с постоянной скоростью, `v 0` плавно останавливает (`vel`) |
| `c <угол> <N>` | N раз туда и обратно на угол от текущей позиции, статистика по каждому ходу (`cycle`) |
| `hold` | держать текущую позицию |
| `x` | освободить вал, нулевой момент (`stop`) |
| `on` / `off` | войти в режим управления / выйти из него |
| `speed <°/с>` | наибольшая скорость ходов, по умолчанию 90 |
| `accel <°/с²>` | наибольшее ускорение ходов и вращения, по умолчанию 180 |
| `kp <Н·м/рад>` | жёсткость, 1–200, по умолчанию 30 |
| `kd <Н·м·с/рад>` | демпфирование, 0–5, по умолчанию 1 |
| `maxt <Н·м>` | предел момента при заклинивании, 1–60, по умолчанию 15 |
| `zero` | текущая позиция становится нулём; только при свободном вале |
| `s` | состояние: режим, уставка, позиция, скорость, момент, температура (`status`) |
| `stats` | статистика; `stats reset` сбрасывает |
| `stream <Гц>` | телеметрия CSV до 100 Гц, `stream 0` выключает |
| `help` | справка |

Команды движения (`m`, `r`, `v`, `c`, `hold`) сами включают мотор.
Остановить движение: `x` и Enter, в крайнем случае выключить ЛБП.

Время хода выбирается так, чтобы не превысить ни `speed`, ни `accel`. Ход на
180° при настройках по умолчанию занимает около 3 с, на 45° — около 1,1 с.
После хода консоль ещё `kMoveHoldMs` (0,5 с) держит цель и печатает итог:

```
Ход 3/4: 4.0° → 34.0° за 0.91 с, ошибка 0.84°, отставание до 6.6°, пик момента 3.48 Н·м
```

Ошибка — позиция вала минус цель после дотягивания. Отставание — наибольшая
разница между уставкой и валом во время хода.

### Статистика

`stats` выводит накопленное с запуска или с `stats reset`:

- связь: команд, ответов, доля потерь, средняя и наибольшая задержка ответа,
  наибольшее число ответов, пропущенных подряд;
- ходы: число ходов, ошибка в конце (средняя со знаком, СКО, наибольшая),
  наибольшее отставание и пиковый момент;
- наибольшие момент, скорость и температура за всё время;
- сколько циклов управления работало ограничение момента и сколько было
  аварийных остановок.

`c` в конце печатает такую же сводку только по своим ходам. СКО ошибки в цикле
показывает повторяемость позиционирования.

### Телеметрия

`stream 50` печатает 50 строк в секунду:

```
t_ms,mode,p_ref_deg,pos_deg,vel_dps,torque_nm,temp_c,error
15070,V,12.41,5.89,38.6,3.20,24,0
```

`mode`: O не в режиме управления, L вал свободен, H удержание, M ход,
V вращение. В режиме O мотор не опрашивается, значения в строке последние
известные (нули, если мотор ещё не отвечал). Строки телеметрии начинаются с
цифры, сообщения консоли с буквы.
Записать весь вывод в файл (он появится в текущей папке), затем отобрать
строки, начинающиеся с цифры:

```bash
pio device monitor -f send_on_enter -f log2file
grep '^[0-9]' platformio-device-monitor-*.log > telemetry.csv
```

Строку заголовка `t_ms,mode,...` консоль печатает при каждом `stream <Гц>`,
её нужно добавить в начало `telemetry.csv`.

### Защита

- Уставка не отходит от вала дальше, чем позволяет `maxt`: если вал заклинит,
  момент не превысит `maxt`. Если вал не догоняет уставку дольше 0,5 с,
  консоль освобождает вал.
- Позиция ограничена ±687° (диапазон MIT-режима ±12,5 рад). Вращение
  тормозит перед пределом само.
- При коде ошибки мотора, температуре от `kMaxTemperatureC` или 10 командах
  подряд без ответа вал освобождается. Когда связь вернётся, консоль снова
  переводит мотор в режим управления, вал остаётся свободным.

На стенде с ЛБП 30 В / 1 А короткие быстрые ходы (45° за 0,8 с, пик 5 Н·м)
однажды оборвали связь на 2,6 с, после чего мотор отвечал, но команды не
выполнял, как после перезагрузки. Вероятная причина — просадка напряжения на
ограничении тока. С ограничением ускорения 180 °/с² это не повторилось, но
ограничение тока ЛБП лучше поднять до 2–3 А.

## Если не работает

| Сообщение | Что проверить |
|---|---|
| MCP2515 не отвечает по SPI | провода SPI и CS, питание модуля 5 В; тест печатает CANSTAT и CANCTRL (см. ниже) |
| Нет ответа от мотора | счётчики ошибок CAN (таблица ниже), питание мотора, `kMotorId`, кварц |
| похоже, он в Servo-режиме | переключить мотор в MIT через CubeMars Upper Computer |
| слишком много потерянных ответов | кварц 8 МГц, длина и качество проводов CAN, терминаторы |
| вал не пришёл в заданную позицию | вал заклинен или нагружен; при сильном трении увеличить `kMoveKp` |

При ошибке SPI тест читает регистры MCP2515 напрямую на 1 МГц. Норма после
сброса: CANSTAT 0x80, CANCTRL 0x87. 0xFF значит, что модуль не отвечает (CS,
SO, питание), 0x00 — линия SO прижата к земле. Если на 1 МГц значения верные,
плохой контакт или слишком длинные провода SPI. Dupont-провода на стенде
отходили не раз, после переподключения SPI работал.

TEC и REC — счётчики ошибок передачи и приёма у MCP2515, EFLG — флаги ошибок.
По ним видно, на каком уровне проблема:

| TEC, REC, EFLG | Что значит | Что делать |
|---|---|---|
| TEC=0, REC=0, EFLG=0x00 | шина исправна, мотор подтверждает кадры, но не отвечает | не тот `kMotorId` или режим: `test_bus_scan` |
| TEC≥128, EFLG=0x15 или 0x35 | кадры уходят, но их никто не подтверждает | питание мотора, обрыв CAN_H/CAN_L |
| TEC=0, REC=128, EFLG=0x0B | контроллер видит на шине доминант и не может начать передачу | терминатор J1, проводка и разъём мотора (CAN in/out) |

Чтобы отделить модуль от проводки, отключите провода CAN от мотора и
поставьте J1. Исправный модуль в одиночку даёт TEC=128, EFLG=0x15.

## Протокол

MIT-режим по мануалу *AK Series Module Driver User Manual V1.0.15*, раздел 5.3:

- стандартный кадр, ID равен ID мотора, 8 байт данных;
- диапазоны AK80-64: позиция ±12,5 рад, скорость ±8 рад/с, момент ±144 Н·м,
  Kp 0–500, Kd 0–5.

Масштаб поля момента в ответе берётся из диапазона момента. Его стоит один раз
сверить на стенде, например с динамометром на плече известной длины.

Код протокола (`lib/ak80_mit`) не зависит от Arduino и CAN-драйвера, его можно
перенести в `firmware/lib/ak_motor`. В примере кода из мануала есть ошибка
переполнения: значение `P_MAX` кодируется как `P_MIN`. Здесь она исправлена и
закрыта тестом.
